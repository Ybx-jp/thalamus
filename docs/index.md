| 2026-08-09 | **The quick protocol is built, and every launcher obligation is enforced rather than documented.** `thalamus quick ask <expert> "<q>"` resolves the one live session pinned to that scope from `$CLAUDE_CONFIG_DIR/sessions/*.json` (pid + `procStart` liveness, refusing on 0 or ≥2), refuses a mid-turn parent unless `--force-busy`, mints a `protocol: quick` Exchange carrying `brief_served: false` and the degenerate grant *before* forking, launches with the parent's own `--agent`, a pre-assigned `--session-id` and `THALAMUS_FORKED_FROM`, then prices the call (`wall_ms`, `cost_usd`, both cache fields, `cache_hit`) and closes through the unchanged `consult_answer` gate. `protocol` is a new field beside `kind`, which keeps classifying the question. Two things are counted rather than asserted: `fresh_recalls`, read off the fork's own records, and the fork's pin-ledger row, whose divergence blocks acceptance and leaves the exchange open with the reason recorded. Forked sessions distill their **delta** — `thalamus quick delta` stages the UUID set difference under `~/.thalamus/forks/` and `session-end.sh` extracts from there whenever `forked_from` is set. | Building it changed three things the design left open. (1) `kind: quick` as written would have overwritten the design/general classifier that fires the readiness check, so the tier is its own field. (2) The fresh recall was an instruction to the fork with no way to tell a fork that did it from one that said it did — the delta the distillation already needs makes it countable, so the tier's own invariant is measured at the moment it matters. (3) Delta distillation keys on `forked_from`, not on the quick protocol: the duplicate-episode failure is a property of `--fork-session`, so keying it to one caller would have left every other fork duplicating. A missing ledger row is treated as divergence, not absence of evidence — the same rule the brief's recorded absence follows. See [02](02-expert-subgraphs.md), [07](07-harness-integration.md). |
| 2026-08-09 | **The sycophancy direction was backwards, the latency comparison was malformed, and the room answers the recency worry.** Three corrections to the quick protocol, all operator-caught. (1) A fork inherits **its own** prior context, not the caller's, so the bias inherited context predicts is **self-anchoring** — which against a false premise makes a warm expert *more* likely to push back. Caller-agreement is a **room** correlation (shared phase-1 framing), already marked by `room`, not a fork one. "A fork is the maximal case of conditioning-raises-agreement" is withdrawn, and the tripwire becomes a two-sided **interaction** test: does warmth flatten or steepen SWAY's confidence→agreement slope? (2) Every timing so far used a one-word prompt, so it measured **fork overhead**, not response latency; comparing it to the end-to-end 303–462 s cold baseline was a category error and the "~5× better" claim is withdrawn. (3) The "roster is normally idle" cost worry came from the *solo* roster — a room is a co-working cluster, so warm is the common case there. | The tier gate is re-derived on the corrected mechanism: cross-role review between different scopes, pins and goals is **peer** review, and self-enhancement bias needs the judge and the judged to be the same trajectory. So the gate is **prior commitment**, tested operationally — is the artifact under review already in the fork's inherited context? — rather than the grammatical mood of the question. What survives of the cost worry is narrower and still open: warmth decays inside the nominal TTL, and non-interruption steers `quick` toward a mid-turn parent, which is the 13× case. |
| 2026-08-09 | **A warm fork is cheap, and the quick protocol's cost is bimodal on parent *recency* — the first "$1.35 per call" finding is withdrawn.** A fork of a parent active seconds ago reads that parent's whole prompt-cache prefix and creates only the new turn (121,938 read / 15 created, 100%, **$0.037 against $0.595 cold**). Session id and `--name` are not in the cached prefix; a fork writes no competing entry (N calls = one write + N−1 reads); matching the parent's `--agent` is free while mismatching costs a full miss. So: ~$0.03–0.08 warm, $0.55–1.35 cold or mismatched, **13× mid-turn**, and 44.8% at 38 minutes. `quick` logs both cache fields and prefers a parent between turns. See [lab/049](../lab/049-the-fork-is-the-whole-conversation.md). | The withdrawn figure forked **stale fixtures** and reported `cache_creation_input_tokens` while never reading `cache_read_input_tokens` — it measured the one regime the protocol never runs in, which is lab/043's error in a new costume: a measurement of the cold regime is not a measurement of the harness. Caught by the operator asking whether forks share the parent's cache. Two consequences the correction does *not* dissolve: a mid-turn fork misses the message body, so non-interruption steers the protocol into its own expensive case; and the roster's normal state is idle (live `teacher` sessions at ~25,700 s), so a call against an untouched expert is a cold call and the expected price rests on a usage distribution nobody has measured. |
| 2026-08-09 | **Dropping `--agent` on a fork is silent, not merely wrong.** A fork of a pinned parent without `--agent` still reads the **pinned** prefix (113,330 tokens, not the unpinned 121,938) — inferring that `--resume` restores the expert's system prompt from the session's own record — while its pin-ledger row records `scope=main, agent=""`. So the fork answers in the expert's voice and files as `main`, with nothing in the answer text showing the divergence. `thalamus quick` passes the parent's own agent and asserts the resulting ledger row before accepting the answer. | Strengthens the earlier scope-crossing finding rather than replacing it: the original read was that an unpinned fork serves the wrong memory, which is visible in a bad answer. The cache measurement shows the *model* side is right and only the *record* side is wrong — the failure mode with no symptom, and the one that quietly moves an expert's episode across a scope boundary. |
| 2026-08-09 | **The quick protocol is a second consultation tier, and warmth is a cache that must be revalidated rather than trusted.** Inside a room, a caller answers a blocking question by forking the expert's own live session (`claude -p --resume <sid> --fork-session`) instead of spawning a cold subagent; the parent is never signalled. The tier keeps the exchange record in full and the citation gate unchanged, and adds **one fresh in-ticket recall** — the drops are the brief (its absence recorded as a fact) and the grant's *format*, not its presence: a compact assertion that this fork inherits parent P's scope S as of fork point F. Tier is chosen by question type — lookups quick, judgments of the caller's in-flight work to the full ticket. Every quick exchange prices itself. See [02](02-expert-subgraphs.md), [07](07-harness-integration.md), [lab/049](../lab/049-the-fork-is-the-whole-conversation.md). | The full ticket's cost is not the mint or the brief but the cold subagent recalling its way to competence (303–462 s measured). A fork skips that — but "the fork already holds vertex IDs from its parent's recalls" concedes the case: those were retrieved for a *different* question, so the gate would validate resolvability rather than relevance, naive RAG serves the superseded value 15–40% of the time and a fork has no supersession mechanism at all, and position bias degrades exactly the mid-transcript region the argument leans on. One fresh recall costs about the embedding floor and buys revalidation, adjacent tier labels, and a citation in the position-favoured region. The type gate is contagion coefficient 1 and self-enhancement bias: a fork has no independent believer left to disagree. |
| 2026-08-09 | **A quick fork distills its delta, not its transcript — and neither the pin nor `forked_from` survives a resume.** A fork's JSONL is the parent's whole conversation restamped with the fork's `sessionId` and the parent's message UUIDs verbatim (562/562), so distilling it as an ordinary session mints a second Session re-asserting the parent's episode plus a second un-dedupable archived Source. ## Bootstrapping memory

The prior project's memories were deliberately **not** carried over; memory is being
re-derived from this machine's own session transcripts. See
[10-evidence-archive.md](10-evidence-archive.md).

**Both stages are built and have run over the full corpus** (2026-07-15). Stage 1
(`thalamus bootstrap`): transcripts retained in the immutable, content-addressed archive
at `~/.thalamus/archive/`; `Source` / `Session` / `Artifact` / anchored `TOUCHES` derived
from tool-call records with no model in the loop — 64 sessions, zero contract rejections.
Stage 2 (`thalamus extract`): claims and threads extracted via headless `claude -p`,
merged into the deterministic layer, chronologically so threads resolve forward in time —
**63 sessions, 1,089 claims, 196 threads (45 resolved, 90 continued by later sessions),
~$30 of model time.** The graph now holds ~2,459 vertices and ~4,918 edges. Memory is
live in this repo: the MCP server and SessionStart/SessionEnd/PostToolUse hooks are
installed, so new sessions recall at start, distill themselves at end, and leave
retrieval traces for M2. See [10](10-evidence-archive.md) for what the first full run
taught, including the finding that content-addressed claim convergence never fired.

Allowlisted: `stepmania-chart-generator` (69 transcripts) and `thalamus`. **Not** the
home-directory sessions — they contain résumé/personal history and the media-server work,
which carries VPN credentials.

Ordering was load-bearing, and it is why M0.5 came first: bootstrapping against the old
schema would have produced a corpus with no provenance, tier, or scope — the retrofit
[05](05-trust-model.md) calls the canonical mistake, reached by a different road.
