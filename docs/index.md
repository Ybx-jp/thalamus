## Decision log

| Date | Decision | Why |
|---|---|---|
| 2026-07-27 | **The substrate is TinkerGraph, and durability is a write-path obligation.** Gremlin Server 3.7.3 over TinkerGraph replaces the licensed backend; `config/tinkergraph.properties` sets `ANY` id managers (Thalamus mints its own scope-qualified string VIDs, which the default `LONG` manager rejects) and a gryo `graphLocation`. Because TinkerGraph writes that file only on a clean close, every write path (`write`, `bootstrap`, `extract`, `ingest`, `eval sync`, MCP `memorize`) flushes via the io()-step when it finishes, and `thalamus snapshot` does it on demand. Migration was read-and-replay — every vertex and edge ID preserved verbatim, since the archive, the pin ledger and eval traces all reference them. | The quick start required an enterprise feature key and a vendor account, which is a hard stop for anyone cloning the repo, and the licence was not redistributable — an entanglement a public repo should not carry. The port cost was configuration, not code: the substrate has only ever spoken remote Gremlin (`ws://localhost:8182`), so `merge_v`/`merge_e`, the text predicates and the orphan audit all moved unchanged, verified against a throwaway server before the live cutover. The trade taken knowingly: in-memory means a hard kill costs whatever was written since the last flush, which is why the flush is automatic rather than documented. |
| 2026-07-27 | **Orphans are dropped in the move, not replayed and deleted.** The 1,105 zero-degree `Claim` vertices left behind by the 2026-07-15 identity re-keying were excluded from the migration export by computing the connected set from the edge endpoints. `contract check` on the new substrate reports zero orphans against 4,358 vertices / 10,438 edges. | A migration is the one moment when discarding is free — replaying 1,105 known-bad vertices in order to issue 1,105 deletes afterwards buys nothing and leaves a window where the audit fails. Computing the keep-set from edge endpoints rather than from a `where(both_e().count().is_(0))` filter is deliberate: that formulation silently returned 0 on the old provider (gremlin-python RECIPES.md), so the export trusts the edge list, which is checked for dangling endpoints before anything is written. |
| 2026-07-27 | **The arm gets a repo that stops at its ref, and a container the operator's checkout is not in.** `prepare_worktree` replaces `git worktree add` with a `--depth=1` fetch of the single pinned commit (full 40-char SHA, `allowAnySHA1InWant` passed to the *remote* side via `--upload-pack`, so no temp branch and nothing left in the operator's repo). `--sandbox` runs the session in `docker/arm-runner.Dockerfile` with the toolchain mounted from the host for version parity; `--isolate-store` additionally cuts the network for surface-less arms, closing the memory-off store hole. A task whose own battery file exists at its ref is **refused**. Detection (`detect_worktree_escape`, `detect_history_reach`) keeps running after the fix. See [04](04-eval-loop.md) layer 2, lab/022. | Two leak channels, both measured: 3 of 24 arms read the operator's checkout by absolute path, and **9 of 88 reached past their pinned ref through the shared git object store** — one ran `git grep -l "<task-id>" $(git rev-list --all)`, another `git show <reader fix_ref>`, so pre-grading campaigns are implicated too. The git channel is invisible to filesystem confinement because the object store is what git needs to run. Deleting the battery from the checkout was tried and fails L1 for every candidate (the pinned suite asserts ≥2 tasks) — lab/019's ungradeable-design defect again, so the check refuses instead. Measured, not assumed: bwrap is blocked by `apparmor_restrict_unprivileged_userns=1`, and Docker **Desktop** is the wrong daemon (VM ⇒ restricted mounts, `--network host` is the VM's host). Detection survives because environmental interaction is a first-class provenance step — denying silently would turn a measured behavior into an absence. |
| 2026-07-27 | **Arm contamination is stamped, and it is not `attributable`.** `detect_worktree_escape` reads each arm's transcript for tool inputs naming the operator's checkout and records `escapes` + `contaminated`; the `answer_key` class covers battery files **and** any file the task's own `fix_ref` changed, derived per-task by `fix_touched_paths` rather than from a fixed directory list. Flag, never exclude: the rung stands as measured, `contaminated` is the pre-registered exclusion key for a *per-protocol* read, and the intention-to-treat comparison keeps every arm. See [04](04-eval-loop.md) layer 2, lab/021. | lab/020 caught two leaked arms by hand and named confinement as blocking; confinement is unbuilt and detection was cheap. Validated against that campaign's own 27 arms: reproduces both, no false positives, and finds a third that had run the live `arms.py` — which already carries the fix — so the corrected rate is **3 of 24, not 2**. An infra fault means the verdict is not about the candidate at all; contamination means it is about the candidate but not an *unaided* one, and collapsing them loses both. |
| 2026-07-27 | **Ordinal rungs are not averaged.** Campaign reporting uses the rung distribution and a pre-registered threshold (share ≥ k); `mean rung` is retired and lab/019's sd-in-rungs power arithmetic is marked unwarranted pending a proportional-odds replacement. Two hazards are named rather than fixed: the worktree runs the MCP server from **pinned** source, so a memory-on arm on `reader-case-insensitive-recall` calls `memory_recall` through the very bug it is asked to fix (asymmetric, biased *against* memory-on); and an expert scope has no route back to `main` — `memory_query` is main-pin-only and refers callers to a consultation ticket, but `main` has no expert manifest. See lab/021. | docs/04 already refuses interval treatment **for the score** (cardinality bias, arXiv 2601.03525) and the analysis layer reimported it — lab/017's own generalization, one layer down. Not academic: on lab/020's data the reported mean (2.25 vs 2.33) points *opposite* to that campaign's pre-registered primary endpoint (3/12 vs 2/12). Literature consultations `scope:main:exchange:ccbee4b6098b4295` → `1273642c41064119` confirmed by scope census that ordinal-as-interval, ITT/per-protocol and ordinal power are unheld; Liddell & Kruschke (2018) is rank-1 demand-driven procurement. |
| 2026-07-19 | **No arm writes memory; neutral discipline stays on everywhere.** The arm runner strips SessionEnd distillation and the PostToolUse trace taps in *every* arm, memory-on included — memory-on means the read surface is on. ## Bootstrapping memory

The prior project's memories were deliberately **not** carried over; memory is being
re-derived from this machine's own session transcripts. See
[10-evidence-archive.md](10-evidence-archive.md).

**Both stages are built and have run over the full corpus** (2026-07-15). Stage 1
(`thalamus bootstrap`): transcripts retained in the immutable, content-addressed archive
at `~/.thalamus/archive/`; `Source` / `Session` / `Artifact` / anchored `TOUCHES` derived
from tool-call records with no model in the loop — 64 sessions, zero contract rejections.
Stage 2 (`thalamus extract`): claims and threads extracted via headless `claude -p`,
merged into the deterministic layer, chronologically so threads resolve forward in time —
**63 sessions, 1,089 claims, 196 threads (45 resolved, 90 continued by later sessions),
~$30 of model time.** The graph now holds ~2,459 vertices and ~4,918 edges. Memory is
live in this repo: the MCP server and SessionStart/SessionEnd/PostToolUse hooks are
installed, so new sessions recall at start, distill themselves at end, and leave
retrieval traces for M2. See [10](10-evidence-archive.md) for what the first full run
taught, including the finding that content-addressed claim convergence never fired.

Allowlisted: `stepmania-chart-generator` (69 transcripts) and `thalamus`. **Not** the
home-directory sessions — they contain résumé/personal history and the media-server work,
which carries VPN credentials.

Ordering was load-bearing, and it is why M0.5 came first: bootstrapping against the old
schema would have produced a corpus with no provenance, tier, or scope — the retrofit
[05](05-trust-model.md) calls the canonical mistake, reached by a different road.
