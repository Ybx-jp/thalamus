The pre-registered endpoint reads null, and it is not where the effect is

Rung 4 — the task's own memory-attributable outcome, fixed in its YAML before any campaign — was reached by 0 of 6 ceiling arms and 0 of 6 memory-off arms. Neither arm ever got there.

Every difference sits at rung 3, which this experiment pre-registered as exploratory: 5/6 for memory-off against 0/6 for the ceiling. That placement error is the one lab/023 made, and the reason it is reported this way rather than quietly promoted is that the rule was written down first.

The direction is the finding

The ceiling arm was not merely no better. It was worse in every pair — 1 wins, 5 losses, 0 ties, sign test p = 0.219. The confidence sequence at n=6 spans [-0.729, 1.396] and does not exclude the null: it is an anytime-valid bound over an unbounded horizon and needs roughly an order of magnitude more pairs at this effect size. Both are reported, because quoting only the friendlier one is what lab/023 did wrong.

Effort, because an outcome alone cannot separate "the memo told me the answer so I stopped" from "the memo did not help". Read the 41s as the 40-turn cap, not as diligence: a capped arm was cut off mid-work and its rung is a lower bound.

A conclusion without its path

The ladder is strictly implying. L2 is stop on the death the operator described, reachable from the prompt alone; L4 is a death after real work leaves an attempt of unknown completeness, so it must not be graded. The injected memory is L4/L5 content: "must not guess how complete an interrupted attempt was... two conservative shapes, both ungraded".

So the ceiling arm was handed the advanced requirement and failed the basic one. The reading this suggests — a hypothesis, not a result — is that a distilled memory records the conclusion of a design discussion rather than the path to it, and handed to an agent that has not walked that path the conclusion can substitute for the earlier steps instead of adding to them.

A competing explanation, and the data cannot separate them here. Ceiling arms hit the 40-turn cap far more often than memory-off arms did, so the memo may simply have prompted a larger change that did not fit the budget — scope expansion rather than misdirection. What keeps the comparison alive is that the effect survives dropping every censored arm: among arms that finished inside the budget the separation is still complete. Raising the turn cap is the experiment that would tell these apart, and it has not been run.

What this licenses, and what it does not

The pre-registered falsifier fires: the ceiling does not separate from memory-off on the primary endpoint, so the battery is the binding constraint, and the container campaign and consequence-probe work queued behind it are cancelled rather than rescheduled. Spending more on memory-on/off arms against a battery that cannot register a perfect memory would be buying noise.

  • One task. The battery has exactly one strongly-gated task, so this is a statement about that task's gate. Generalising it to "memory does not help" is unsupported by construction.
  • One model, one operator, one harness configuration.
  • The mechanism is unconfirmed. Arm worktrees are cleaned after each run, so the diffs that would show whether the candidate built the refinement and skipped the foundation were not retained. That check needs one more arm with the worktree kept, and it sits outside the registered design.
  • The memo is one phrasing. Whether the effect survives a memo that states the problem rather than the conclusion is the obvious next experiment, and it is not this one.

Confinement, confirmed live for the first time

Every arm ran in a container without the operator's checkout and without a route to the graph. 4 arm(s) loaded tool schemas and still reached no memory tool: the arms tried, and could not. Until this campaign confinement had only been verified by direct probe, never by a live run.

What is deliberately absent

The graph itself is not published. It is one operator's session history and the evidence archive holds their transcripts verbatim — credentials, client names and personal history included. The snapshot hash lets anyone holding the same state verify that these numbers came from it; it does not let a stranger recompute them from scratch, and no wording here should imply otherwise.
