# Pre-registration — experiment 003

Committed **2026-07-30**, **before any withholding draw has been recorded**. At the
time of writing `THALAMUS_WITHHOLD` has never been set, `~/.thalamus/policy/` is
empty, and no `Trace` in the graph carries a propensity. That ordering is the point:
this file exists so the design cannot be chosen after the data.

## Question

When a memory the ranker would have shown is withheld at random, does the session
behave differently?

Everything measured so far is correlational. Experiment 001 shows the used-vs-ignored
judge carries κ≈0.14 of the available headroom and that no rearrangement of the same
lexical evidence improves it; experiment 002 shows the token figure it feeds cannot be
made precise by waiting. Both grade a set the *ranker chose*. This is the first design
in which something is done differently on purpose.

## Design

Within-session randomization with carryover — a switchback. Injected tokens ride along
in every later API call of a session, so a withheld node cannot be treated as a clean
between-unit assignment.

- **Unit of randomization:** the individual node inside a retrieval.
- **Treatment:** withheld from the render.
- **Assignment:** independent per node at rate `THALAMUS_WITHHOLD`, seeded from the
  retrieval's own identity, seed stored (`eval/policy.py`).
- **Rate:** 0.25, fixed here. High enough to accumulate discordant pairs, low enough
  that a working session is not visibly degraded.
- **Never fully withheld:** a retrieval always renders at least one node, because an
  empty render is a *miss* and the tap cannot distinguish those.

## Primary endpoint

The **rate at which a retrieval is followed by a repeat retrieval on overlapping
terms within the same session**, comparing retrievals that had nodes withheld against
retrievals that did not.

Chosen over any used-rate on purpose. A withheld node has no verdict — it never
reached the agent — so an endpoint built on verdicts would be defined by the
intervention. Re-asking is a behaviour the agent emits, is visible in the tap without
a judge, and is the behaviour a *missing* memory should provoke.

## Secondary endpoints

Reported, never promoted to primary regardless of what they show:

1. Session-level: retrievals per session, and total injected tokens per session.
2. Judge-side: used-rate on the nodes that *were* rendered, under withholding vs not.
3. Inverse-propensity-weighted used-rate over the whole log — the estimator the
   propensities exist to license.

## Analysis

Exact randomization inference against the recorded assignment: the reference
distribution is generated by re-drawing assignments from the stored seeds, not from a
parametric null. Reported with a confidence sequence (`eval/sequential.py`,
α = 0.05, ρ = 0.05), so the run may be inspected without spending its own error rate —
lab/023 is this project's demonstration of what happens otherwise.

## Stopping rule

Whichever comes first:

1. the confidence sequence excludes the null;
2. the sequence lies entirely inside ±0.05 of the null (futility — an effect that
   small would not change any decision here);
3. 400 randomized retrievals.

## Falsifiers

- **The hypothesis fails** if withholding a quarter of rendered nodes produces no
  detectable change in re-asking at the stopping rule. That is a publishable result
  and a cheap one: it says retrieval volume is not doing work, on real traffic,
  without a container campaign.
- **The experiment is void** if fewer than 90% of policy records join to a trace by
  response hash — an unjoined record means the tap and the policy disagree about what
  was rendered, and the assignment cannot be trusted.

## Declared in advance as uninterpretable

- Sessions in which the operator noticed the degradation and changed behaviour
  deliberately. There is no detector for this; it is a threat to validity that the
  single-operator setting cannot remove, and it will be stated in the write-up rather
  than assumed away.
- Any period during which the withholding rate was changed mid-flight. Records carry
  the rate; a run pooling two rates is two experiments.

## Data

`~/.thalamus/policy/*.jsonl` joined to `Trace` vertices by response hash, at a
snapshot pinned when the run stops. Seed for the analysis: `20260730`.
