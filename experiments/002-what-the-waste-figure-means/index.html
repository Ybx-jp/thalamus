Three numbers wearing one name

Thalamus prices every retrieval: the rendered block has a size, and each node in it carries a share. Multiply that share by whether the judge called the node used, and you get the figure the tooling prints — 33.8% of injected tokens wasted.

That figure has been quoted three ways, and they are not the same quantity.

Why the session is the unit

Verdicts inside one session share an output window, a topic and an operator, so they are not independent draws. Measured here: ICC 0.229, design effect 2.52×. Treating 2,445 verdicts as 2,445 observations would report ±1.9pp where the honest interval is ±6.6pp. The estimator is a ratio of totals with a delete-one-session jackknife.

The correction that changes the sentence

The interval above prices sampling error only. The deeper problem is what "used" means: the same judge, pointed at an unrelated session's output, still calls 59.0% of tokens used (experiment 001, token-weighted here rather than node-weighted, because the nodes that dominate the token budget are not the ones that dominate the count).

Correcting for that — κ on the token scale — leaves 17.5% of injected tokens demonstrably earned. The defensible sentence is not "a third of the tokens are wasted". It is:

What the corpus supports

About 17% of injected retrieval tokens are demonstrably earned. The remaining 83% is not distinguishable, by this instrument, from tokens that would have looked equally "used" had they been retrieved for a different session entirely.

That is not a claim that 83% of the memory is useless. It is a statement about the instrument's resolution: it cannot tell the difference, and neither can anyone quoting its output.

This corrected figure has no interval yet, and that is deliberate rather than an oversight. Its uncertainty is the uncertainty of a difference between two rates measured on the same verdicts, which needs the paired estimator experiment 001 built for κ — extended to token weights. Pending that, it is reported as a bound with its inputs shown, not as a point estimate with a false interval.

How much more data would fix the interval

The uncorrected figure's precision is a straightforward function of session count at the variance measured here.

The corrected figure is much harder. Its estimand is a difference of about 7.2 points between two rates on the same verdicts, and verdicts flip under rotation 24.5% of the time. Bounding that difference to ±1 point needs roughly 23,779 verdicts — around 282 sessions at this corpus's 84 verdicts per session, against 29 today.

Precision on the uncorrected figure is reachable; on the corrected one it is not

143 sessions is a matter of months at one operator's working rate. The number needed to pin the corrected figure is an order of magnitude beyond that. So the uncorrected waste rate can be made precise by waiting, and the quantity anyone actually cares about cannot — which is the argument for changing the instrument rather than growing the corpus.

Threats to this result

The per-node price is uniform, and nodes are not

The graph records the size of the whole rendered block and the number of nodes in it, not the size of each node. So the price is injected_chars / returned_count: a 40-token thread title and a 400-token claim in the same retrieval are charged identically. The direction of the bias depends on whether long nodes are used more often than short ones — which is measurable, and is not measured here. Until it is, read every token figure as node-count-weighted in disguise.

Injected once, paid for repeatedly

A retrieval's tokens ride along in every subsequent API call of the session, so the true cost of a wasted retrieval is its size times the number of later calls. The cost module counts that multiplier separately and this experiment does not use it: these are single-injection tokens, which understates the real spend by a factor nobody has pinned.

  • Non-retrieval is invisible. A node that was never returned has no edge, so this frame can price what retrieval cost but never what forgetting cost.
  • One operator, one machine, one harness configuration. The n calculations are superpopulation statements about that operator's future sessions.
  • 27% of verdicts sit on mutable node text (experiment 001): threads and sessions are overwritten latest-wins, so some of these verdicts price text that has since changed.

What is deliberately absent

The graph itself is not published. It is one operator's session history and the evidence archive holds their transcripts verbatim — credentials, client names and personal history included. The snapshot hash lets anyone holding the same state verify that these numbers came from it; it does not let a stranger recompute them from scratch, and no wording here should imply otherwise.
